# Invite Mailer

Invite Mailer – внутренняя система автоматизации приглашений и напоминаний о прохождении тестов.

Текущая версия: **2.3.10**.

## Возможности

- получение актуального XLSX со списком работников из Zimbra по IMAP;
- хранение работников, настроек, истории рассылок и локального кеша в SQLite;
- первичные приглашения и повторные напоминания;
- учет ручной первичной рассылки;
- статусы прохождения по данным Indigo PostgreSQL в режиме read-only;
- уведомления контролирующим после исчерпания напоминаний;
- технические уведомления об ошибках SMTP, Indigo и некорректных доменах;
- управление тестами, шаблонами, контролирующими и настройками через Web UI;
- внутренний HTML-отчет с фильтрами и экспортом;
- сессионная авторизация административного раздела.

## Контейнеры

Проект запускает три контейнера:

- `invite-mailer` – планировщик и команды обработки;
- `invite-mailer-admin` – административный Web UI;
- `invite-mailer-report` – nginx для отчета и маршрутизации административного раздела.

## Быстрый запуск

```bash
mkdir -p /opt/invite-mailer
cd /opt/invite-mailer
cp .env.example .env
docker compose up -d --build
```

Рабочие данные сохраняются вне контейнеров в каталоге `STORAGE_ROOT`. Рекомендуемое значение:

```text
/opt/invite-mailer-storage
```

После запуска отчет доступен по адресу, заданному переменными `REPORT_BIND_IP` и `REPORT_PORT`.

## Настройки

SMTP, Indigo, разрешенные почтовые домены, интервалы и параметры напоминаний после первичного импорта хранятся в SQLite и изменяются через Web UI.

`.env` используется для инфраструктурных параметров и первоначального переноса настроек интеграций. Начиная с версии 2.3.10 значения SMTP и Indigo из `.env` не перезаписывают настройки, уже сохраненные в SQLite.

## Основные команды

```bash
python -m app.main fetch
python -m app.main run --dry-run --skip-fetch
python -m app.main run
python -m app.main reminders
python -m app.main indigo-sync
python -m app.main report
```

Для учета выполненной вручную первичной рассылки:

```bash
python -m app.main seed --templates intro_tests --sent-date 2026-07-13
```

Дата задается в формате `YYYY-MM-DD`.

## Важные ограничения

- перед реальной рассылкой необходимо выполнить `fetch` и тестовый запуск с `--dry-run`;
- подключение к Indigo должно использовать отдельного пользователя только для чтения;
- структура и названия колонок XLSX должны соответствовать настройкам;
- рабочую SQLite нельзя заменять обычным копированием во время активной записи;
- полноценная система автоматических резервных копий и восстановления запланирована на версию 2.4.x.

## Пользователи и права доступа

В версии 2.5.0 добавлен локальный список доменных логинов и три уровня разрешений:

- **Базовый доступ** – просмотр отчета, когда публичный просмотр отключен.
- **Импорт сотрудников** – доступ к импорту списков участников; базовый доступ включается автоматически.
- **Администратор** – полный доступ ко всему функционалу и настройкам.

В разделе «Общие настройки» доступен параметр **«Разрешить просмотр отчета без авторизации»**. При его отключении Nginx проверяет право просмотра через внутренний API приложения.

Учетная запись, заданная параметрами `ADMIN_USERNAME` и `ADMIN_PASSWORD`, остается аварийным локальным администратором и всегда имеет полный доступ.

На этом этапе список пользователей используется как модель авторизации. Проверка доменного пароля Active Directory будет подключена отдельной версией.

## Active Directory

В v2.6.0 добавлены LDAP/LDAPS-аутентификация, поиск пользователей по доменному логину и автоматическое заполнение отображаемого имени. Настройка выполняется в разделе `Настройки` -> `Active Directory`. Подробности: `docs/ACTIVE_DIRECTORY.md`.
