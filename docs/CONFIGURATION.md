# Конфигурация

## Источники настроек

Начиная с версии 2.3.10 действует следующий порядок:

1. При первой инициализации значения SMTP, Indigo и разрешенных доменов импортируются из `.env` и YAML в SQLite.
2. После создания маркера инициализации рабочим источником становится SQLite.
3. Перезапуск контейнеров не переносит значения интеграций из `.env` повторно.
4. Изменения выполняются через Web UI.

## Инфраструктурные параметры `.env`

В окружении постоянно остаются параметры, которые нужны до открытия SQLite или относятся к запуску контейнеров:

- `STORAGE_ROOT`;
- `CONFIG_PATH` и `TEMPLATES_PATH`, когда используются нестандартные пути;
- параметры IMAP;
- `WORKER_HASH_SECRET`;
- `SESSION_SECRET`;
- `SESSION_MAX_AGE_SECONDS`;
- `SESSION_COOKIE_SECURE`;
- локальные учетные данные администратора;
- `REPORT_BIND_IP` и `REPORT_PORT`;
- часовой пояс.

SMTP и Indigo могут оставаться в `.env` как первоначальные значения для новой установки, но после импорта их изменение в `.env` не меняет действующую конфигурацию.

## SMTP

Через Web UI настраиваются:

- сервер и порт;
- SSL, STARTTLS или подключение без шифрования;
- имя пользователя и пароль;
- адрес и имя отправителя;
- Reply-To.

Пустое поле пароля при редактировании сохраняет уже записанный пароль.

## Indigo PostgreSQL

Через Web UI настраиваются:

- включение интеграции;
- сервер, порт и база данных;
- пользователь и пароль;
- `sslmode`;
- тайм-аут подключения;
- представление результатов;
- интервал автоматического обновления от 1 до 1440 минут.

Учетной записи Indigo достаточно права `SELECT` на используемое представление и связанные объекты.

## Почтовые домены

Разрешенные домены вводятся по одному в строке без символа `@`. При включенной проверке адрес с другим доменом считается технической ошибкой и не используется для рассылки.

## Сопоставление логинов

По умолчанию логин определяется как часть корпоративного адреса до `@`. Исключения управляются в административном разделе сопоставления логинов и хранятся в SQLite.

## Секреты

- пароли SMTP и Indigo не возвращаются браузеру;
- Web UI показывает только признак наличия сохраненного пароля;
- файл `.env` и рабочую SQLite нельзя добавлять в Git;
- доступ к каталогу `STORAGE_ROOT/state` должен быть ограничен администраторами системы.


## Получение данных о работниках

Параметры IMAP, отправитель, папка, точное имя XLSX, глубина поиска, время ежедневной проверки и часовой пояс настраиваются в Web. После обновления v2.3.11 существующие значения однократно переносятся из `.env` и `config/config.yaml` в SQLite.

Пустое поле пароля при сохранении не очищает ранее сохраненный пароль.

Доступны операции проверки подключения, поиска последнего подходящего файла и немедленного импорта.
