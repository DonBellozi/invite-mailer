# Переменные шаблонов писем

Шаблоны используют синтаксис Jinja. Для вывода значения применяется запись:

```jinja
{{ fio }}
```

Для условий:

```jinja
{% if test_failed %}
<p>{{ reminder_reason }}</p>
{% endif %}
```

При обращении к переменной, которая не передается выбранному типу письма, формирование письма завершается ошибкой. Перед сохранением рабочего текста рекомендуется отправить тестовое письмо.

## Общие переменные работника

| Переменная | Тип | Описание | Доступна |
|---|---|---|---|
| `fio` | строка | ФИО работника | приглашение, напоминание |
| `email` | строка | Адрес электронной почты | приглашение, напоминание |
| `login` | строка | Логин Indigo | приглашение, напоминание |
| `department` | строка или пустое значение | Подразделение | приглашение, напоминание |
| `position` | строка или пустое значение | Должность | приглашение, напоминание |
| `test_name` | строка | Наименование теста | письма по тесту |

## Напоминание и результат тестирования

| Переменная | Тип | Описание |
|---|---|---|
| `reminder_number` | целое число | Номер отправляемого напоминания, начиная с 1. Первоначальное приглашение не учитывается |
| `reminder_reason` | строка | Готовая универсальная причина напоминания |
| `result_status` | строка | `not_started`, `failed` или `completed` |
| `result_grade` | строка или пустое значение | Результат Indigo |
| `result_percent` | число или пустое значение | Процент результата |
| `attempts` | целое число | Количество учтенных завершенных попыток |
| `successful_attempts` | целое число | Количество успешных попыток |
| `failed_attempts` | целое число | Количество неуспешных попыток |
| `test_started` | логическое значение | Есть хотя бы одна завершенная попытка |
| `test_completed` | логическое значение | Есть действующий успешный результат |
| `test_passed` | логическое значение | То же, что `test_completed` |
| `test_failed` | логическое значение | Есть неуспешная попытка без действующего успешного результата |

Значение `reminder_reason` формируется системой:

- для работника без положительного результата: `Тестирование еще не завершено с положительным результатом.`;
- для работника с неудовлетворительной попыткой: `Тестирование пройдено, но положительный результат не получен. Необходимо пройти тест повторно.`.

Пример универсального напоминания:

```jinja
<p>Здравствуйте, {{ fio }}!</p>
<p>{{ reminder_reason }}</p>
<p>Просим пройти тестирование «{{ test_name }}».</p>
```

Пример условного текста:

```jinja
{% if test_failed %}
<p>Ваша предыдущая попытка не дала положительного результата.</p>
{% else %}
<p>По имеющимся данным тестирование еще не завершено.</p>
{% endif %}
```

## Уведомление контролирующему

В групповом уведомлении доступны:

| Переменная | Описание |
|---|---|
| `reviewer_name` | Наименование или ФИО контролирующего |
| `employees` | Список работников |
| `employees_count` | Полное количество работников в сообщении |
| `displayed_employees_count` | Количество работников, выведенных в сообщении |
| `test_name` | Наименование теста |

Каждый элемент `employees` содержит:

- `fio`;
- `email`;
- `department`;
- `position`;
- `reminder_count`;
- `first_invited_at`;
- `first_reminder_at`;
- `last_reminder_at`.

Пример:

```jinja
{% for employee in employees %}
<p>
  {{ loop.index }}. {{ employee.fio }}<br>
  {{ employee.email }}<br>
  Количество напоминаний: {{ employee.reminder_count }}
</p>
{% endfor %}
```

## Технические уведомления

Набор полей зависит от события. Основные переменные:

- `errors`;
- `errors_count`;
- `fio`;
- `email`;
- `error_type`;
- `error_text`;
- `subject`.

Фактический набор рекомендуется проверять через тестовую отправку соответствующего системного шаблона.
