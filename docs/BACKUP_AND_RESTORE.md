# Резервное копирование

Начиная с версии 2.4.0 приложение создает резервные копии из Web-интерфейса и автоматически по расписанию.

## Хранилище

На сервере рекомендуется использовать отдельный каталог:

```text
/opt/invite-mailer-backups
```

В контейнерах он подключается как:

```text
/backups
```

В `docker-compose.yml` используется переменная `BACKUP_ROOT`. Если она не задана, применяется `/opt/invite-mailer-backups`.

## Состав архива

Архив ZIP содержит:

- согласованный снимок SQLite, созданный через SQLite Backup API;
- каталог `config`, если он существует внутри контейнера;
- каталог `data`, если он существует внутри контейнера;
- `.env` и `docker-compose.yml`, если они доступны внутри контейнера;
- `manifest.json` с версией формата, временем создания, перечнем файлов, размерами и SHA-256 каждого файла.

Рабочая база данных напрямую не копируется.

## Настройки

Раздел доступен по пути:

```text
/admin/settings/backups/
```

Можно настроить:

- включение автоматического резервного копирования;
- час и минуту ежедневного запуска;
- количество сохраняемых успешных копий, по умолчанию 14.

Также доступны ручное создание, скачивание, проверка целостности и удаление архивов.

## Хранение

Ограничение применяется только к архивам, успешно прошедшим проверку. Старые исправные архивы сверх установленного количества удаляются. Поврежденные файлы автоматически не удаляются.

## Восстановление

Автоматическое восстановление будет добавлено в версии 2.4.1. До этого архивы следует использовать только для хранения и ручного аварийного восстановления.
