# Резервное копирование

Начиная с версии 2.4.0 приложение создает резервные копии из Web-интерфейса и автоматически по расписанию. В версии 2.4.1 добавлено восстановление существующих копий.

## Хранилище

На сервере рекомендуется использовать отдельный каталог:

```text
/opt/invite-mailer-backups
```

В контейнерах он подключается как:

```text
/backups
```

В `docker-compose.yml` используется переменная `BACKUP_ROOT`. Если она не задана, применяется `/opt/invite-mailer-backups`.

## Состав архива

Архив ZIP содержит:

- согласованный снимок SQLite, созданный через SQLite Backup API;
- каталог `config`, если он существует внутри контейнера;
- каталог `data`, если он существует внутри контейнера;
- `.env` и `docker-compose.yml`, если они доступны внутри контейнера;
- `manifest.json` с версией формата, временем создания, перечнем файлов, размерами и SHA-256 каждого файла.

Рабочая база данных напрямую не копируется.

## Настройки

Раздел доступен по пути:

```text
/admin/settings/backups/
```

Можно настроить:

- включение автоматического резервного копирования;
- час и минуту ежедневного запуска;
- количество сохраняемых успешных копий, по умолчанию 14.

Также доступны ручное создание, скачивание, проверка целостности, восстановление и удаление архивов.

## Хранение

Ограничение применяется только к архивам, успешно прошедшим проверку. Старые исправные архивы сверх установленного количества удаляются. Поврежденные файлы автоматически не удаляются.

## Восстановление

В таблице «Резервные копии» рядом с действиями «Скачать», «Проверить» и «Удалить» доступна кнопка «Восстановить».

Перед подтверждением система:

- повторно проверяет структуру ZIP и SHA-256 каждого файла;
- показывает дату создания, версию приложения, количество файлов и состав архива;
- не разрешает восстановление поврежденного архива;
- предлагает отдельно выбрать `config`, `data`, `.env` и `docker-compose.yml`, если они присутствуют.

SQLite восстанавливается всегда. Перед заменой данных автоматически создается страховочная копия с типом `pre_restore`. Восстановление SQLite выполняется через SQLite Backup API, а не прямой заменой файла рабочей базы.

После завершения необходимо выполнить показанную в Web UI команду:

```bash
docker compose up -d --force-recreate
```

Страховочная копия остается в общем списке и может быть использована для возврата к состоянию до восстановления.
