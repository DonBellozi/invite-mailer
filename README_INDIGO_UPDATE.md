# Обновление: результаты Indigo и новый отчет

## Что реализовано

- чтение результатов из PostgreSQL Indigo в режиме read-only;
- локальный кеш результатов в SQLite, чтобы отчет продолжал работать при временной недоступности Indigo;
- привязка по нормализованному логину и логическому ID теста;
- для Антитеррора используется `logical_test_id: 1715` и точное название `Антитеррор`;
- для Антикоррупции используется `logical_test_id: 1719` и точное название `Антикоррупция`;
- рабочие копии тестов объединяются через `COALESCE(ph_test_id, test_id)`;
- архивные результаты учитываются;
- `Отлично` и `Хорошо` считаются успешным прохождением;
- результат, начинающийся с `Требуется повторный`, отображается как `Не прошел`;
- дата прохождения берется по последней успешной попытке;
- оценка и процент берутся по лучшей успешной попытке текущей занятости;
- новая успешная попытка переносит срок действия периодического результата вперед;
- результаты прежнего периода трудоустройства не учитываются после повторного приема;
- сопоставления e-mail и логина вынесены в административный раздел;
- прежний `LOGIN_OVERRIDES_JSON` переносится в SQLite один раз и далее управляется через браузер;
- верхняя панель разделена на общую часть и статистику выбранного теста;
- карточка `Ошибки отправки` включает глобальный фильтр по ошибкам всех тестов;
- в списке тестов показывается число участников, например `Антитеррор (456)`.

## Переменные Portainer

Добавьте в Environment variables стека:

```text
INDIGO_ENABLED=true
INDIGO_DB_HOST=10.0.10.16
INDIGO_DB_PORT=5436
INDIGO_DB_NAME=ИМЯ_БАЗЫ
INDIGO_DB_USER=ПОЛЬЗОВАТЕЛЬ_ТОЛЬКО_ДЛЯ_ЧТЕНИЯ
INDIGO_DB_PASSWORD=ПАРОЛЬ
INDIGO_DB_SSLMODE=prefer
INDIGO_DB_CONNECT_TIMEOUT=5
```

Пароль хранится только в переменных Portainer и не записывается в Git.

## Проверка подключения

После Pull and redeploy откройте консоль контейнера `invite-mailer`:

```bash
cd /opt/invite-mailer
python -m app.main indigo-sync
```

Успешный результат выглядит так:

```text
Загружено результатов Indigo: 1234
```

После синхронизации отчет перестраивается автоматически.

## Сопоставление e-mail и логина

В основном отчете откройте `Сопоставление логинов` или перейдите в:

```text
/admin/logins/
```

В разделе можно:

- добавить сопоставление;
- изменить логин для существующего e-mail;
- удалить сопоставление;
- найти запись по e-mail, логину или ФИО.

Изменение сразу применяется к текущей таблице сотрудников и отчету. После удаления снова используется часть e-mail до знака `@`.

## Периодические тесты

Для периодического теста:

```yaml
mode: "periodic"
validity_days: 365
```

Логика:

1. Пока последний успешный результат действует, новое письмо не отправляется.
2. Любая новая успешная попытка, включая добровольную, становится новой датой прохождения и переносит следующий срок вперед.
3. После окончания `validity_days` отправляется одно новое основное приглашение.
4. После нового успешного прохождения начинается следующий период действия.

Повторные напоминания после основного приглашения и отдельная отметка прохождения после срока в это обновление не включены.

## Обновление контейнеров

После изменения стека должны работать:

```text
invite-mailer
invite-mailer-admin
invite-mailer-report
```

Если после пересоздания административного контейнера nginx временно показывает `502 Bad Gateway`, перезапустите контейнер:

```bash
docker restart invite-mailer-report
```
