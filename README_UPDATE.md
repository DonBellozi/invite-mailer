# Обновление: импорт выборочных списков участников

## Что добавлено

- отдельный внутренний раздел `/admin/` для загрузки XLSX;
- сопоставление участников по нормализованному email с основной таблицей `employees`;
- предварительная проверка без создания назначений;
- ФИО, подразделение, должность и логин берутся только из основной ежедневной загрузки;
- корректные строки можно подтвердить выборочно;
- ошибки не блокируют импорт остальных работников;
- отдельный XLSX-отчет по ошибкам и предупреждениям;
- выборочные тесты участвуют в обычном `dry-run`, рассылке и общем HTML-отчете;
- команда `seed` больше не отмечает уведомленными сотрудников без email;
- изменения `LOGIN_OVERRIDES_JSON` повторно применяются даже к уже обработанному ежедневному XLSX.

## 1. Настроить выборочный тест

В существующий `config/templates.yaml` добавьте шаблон. Не заменяйте свои текущие шаблоны.

```yaml
  - id: "special_test"
    enabled: false
    name: "Название выборочного теста"
    subject: "Приглашение к прохождению тестирования"
    body_template: "/opt/invite-mailer/templates/special_test.html"
    mode: "once"
    validity_days: null
    audience:
      type: "explicit_list"
```

Пока письмо и список проверяются, оставьте `enabled: false`. После подтверждения состава и текста письма переключите на `enabled: true`.

## 2. Настроить авторизацию

В переменные окружения стека Portainer добавьте:

```text
ADMIN_USERNAME=admin
ADMIN_PASSWORD=ДЛИННЫЙ_СЛУЧАЙНЫЙ_ПАРОЛЬ
```

Пароль не следует хранить в Git.

## 3. Обновить стек

После commit и push выполните **Pull and redeploy**. Должны работать три контейнера:

```text
invite-mailer
invite-mailer-admin
invite-mailer-report
```

Новые таблицы SQLite создаются автоматически при старте контейнера. Существующие сотрудники, история отправок и настройки сохраняются.

## 4. Импортировать список

1. Откройте основной отчет.
2. Нажмите **Импорт списков участников**.
3. Введите административный логин и пароль.
4. Выберите тест и XLSX.
5. Нажмите **Проверить файл**.
6. Просмотрите найденные ФИО, подразделения, должности и логины.
7. Снимите флажки с ошибочно включенных работников.
8. Нажмите **Подтвердить N назначений**.

Из загружаемого XLSX используется только колонка email. Поддерживаются заголовки `Email`, `E-mail`, `Электронная почта`, `Адрес электронной почты` и заголовки, содержащие эти фразы.

## 5. Проверить очередь

После подтверждения списка:

```bash
cd /opt/invite-mailer
python -m app.main run --dry-run --skip-fetch
```

Когда шаблон имеет `enabled: false`, его назначения отображаются в отчете, но письма не входят в очередь. Для реальной или тестовой отправки шаблон нужно включить.

## Результаты проверки строк

- `Готово к назначению` – сотрудник однозначно найден и еще не назначен;
- `Уже назначен ранее` – повторное назначение не создается;
- `Дубликат в файле` – повторный email пропускается;
- `Не найден в основной базе` – email отсутствует у активных сотрудников;
- `Найден только неактивный сотрудник` – отправка не планируется;
- `Несколько совпадений` – один email указан у нескольких активных сотрудников;
- `Нет логина` – сотрудник найден, но отправка блокируется до исправления логина;
- `Некорректный email` – значение не распознано как адрес.

## Веб-авторизация и выход

Начиная с версии 2.3.7 браузерная HTTP Basic-авторизация заменена на страницу входа и серверную сессию.

Используются переменные окружения:

- `ADMIN_USERNAME` – встроенный логин;
- `ADMIN_PASSWORD` – встроенный пароль;
- `ADMIN_DISPLAY_NAME` – имя, отображаемое на кнопке в отчете;
- `SESSION_SECRET` – секрет подписи сессии, рекомендуется случайная строка длиной не менее 32 символов;
- `SESSION_MAX_AGE_SECONDS` – срок жизни сессии, по умолчанию 28800 секунд;
- `SESSION_COOKIE_SECURE` – установить `true`, когда сайт работает только через HTTPS.

На странице отчета появилась третья кнопка. До входа она показывает `Войти`. После входа показывает имя пользователя, а при наведении меняется на `Выйти`.
